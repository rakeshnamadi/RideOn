# Database design

MySQL 8.4 via Prisma 6. Schema: `apps/api/prisma/schema.prisma`. Migrations: `apps/api/prisma/migrations/`.

## Conventions

- Primary keys are CUIDs (`VARCHAR(191)`), generated by Prisma.
- **Money is integer paise** in columns ending `Paise`. Percentages are integer basis points (`…Bps`).
- **All timestamps are UTC.** Local service time (schedules, night fares, earnings days) uses the city's IANA timezone (`cities.timezone`, default `Asia/Kolkata`).
- Status columns are MySQL enums with transitions enforced in code (`modules/bookings/state-machine.ts`) and by conditional updates.
- Rows that represent decisions are never edited in place: fare rules are versioned, audit and fare history are append-only.

## Entity groups

### Identity and authorisation
| Table | Purpose |
|---|---|
| `users` | Accounts (phone unique, optional email unique), status, lockout counters, trusted contact |
| `roles`, `permissions`, `role_permissions`, `user_roles` | Global RBAC (`SUPER_ADMIN`, `COMMUNITY_ADMIN`, `DRIVER`, `PASSENGER`) |
| `sessions` | Refresh-token sessions: HMAC of token, family id for reuse detection, rotation and revocation timestamps |
| `user_consents` | Terms, privacy and location consents with version and time |
| `password_reset_tokens` | SHA-256 of single-use reset tokens, 30-minute expiry |

### Communities and governance
| Table | Purpose |
|---|---|
| `cities` | Supported cities with timezone and map centre |
| `communities` | Driver associations; `status` PENDING/ACTIVE/SUSPENDED/DEACTIVATED |
| `community_admins` | Community-scoped roles (HEAD/ADMIN/APPROVER/OPERATOR), unique per (community, user) |
| `community_memberships` | Driver ↔ community, APPLIED/APPROVED/REJECTED/SUSPENDED/LEFT, decision notes |
| `community_service_areas` | Pickup polygons (`polygon` JSON `[lat,lng][]`) |
| `community_policies` | 1:1 operating and governance policy (approval mode, approvals required, notice period, cancellation rules, timeouts, hold time) plus platform-set limits (max increase, distance fares, community fee) |
| `governance_proposals` | Proposals of type FARE_CHANGE (details in `fare_proposals`) or POLICY_CHANGE (`policyChanges` with `policyBefore` for display); status, approvals required, platform review fields, effective time |
| `governance_votes` | One vote per (proposal, voter) |
| `fare_proposals` | 1:1 fare details of a FARE_CHANGE proposal |
| `announcements` | Community announcements with audience |

### Drivers and vehicles
| Table | Purpose |
|---|---|
| `drivers` | 1:1 with user; licence (unique), verification status, suspension, rating aggregates |
| `driver_documents` | Metadata for privately stored files (random storage key, content-sniffed MIME, review status) |
| `vehicles` | Registered to a community; registration number unique; **seat capacity set by the community** |
| `driver_vehicle_assignments` | History of which driver uses which vehicle |
| `driver_availability` | 1:1 live status OFFLINE/ONLINE/ON_TRIP, operating community, stand queue position |
| `driver_locations` | **Latest location only**, one row per online driver, deleted when offline or stale |

### Places, routes and fares
| Table | Purpose |
|---|---|
| `pickup_points` | Stands and stops (`isStand`) |
| `shared_routes` | Route code (unique per community), max seats, booking/cancellation cutoffs, boarding rules, road path through the stops |
| `route_stops` | Ordered stops; unique (route, sequence) and (route, pickup point) |
| `route_schedules` | Local departure time, weekday bitmask, seat capacity, validity window |
| `fare_rules` | Versioned, effective-dated rules for REGULAR (per community) or SHARED (per route) |
| `fare_history` | **Append-only** record of every published fare change |
| `fare_quotes` | Server-issued prices a booking must reference (expiry, single use) |

### Bookings and trips
| Table | Purpose |
|---|---|
| `bookings` | Both booking types; reference unique; `status` and separate `paymentStatus`; unique (passenger, idempotency key); quote unique; optimistic `version` |
| `booking_assignments` | Driver offers per dispatch round; unique (booking, driver) |
| `booking_status_history` | Every transition with actor type and reason |
| `shared_trip_instances` | A dated departure; unique (schedule, departureAt); `seatsBooked` counter with `CHECK (0 ≤ seatsBooked ≤ capacity)` |
| `seat_reservations` | One row per seat; **`activeSeatKey` unique** while HELD/CONFIRMED/BOARDED, NULL otherwise |
| `trip_events` | SOS, boarding, no-show, route deviation, delays, trip sharing |
| `ratings` | One per (booking, rater), `CHECK score 1–5` |
| `complaints` | Complaints, disputes and driver appeals with status and resolution |

### Payments and operations
| Table | Purpose |
|---|---|
| `payments` | Attempts per booking; provider ref unique; idempotency key unique; **`successKey` unique** (= bookingId once SUCCEEDED) prevents double charging |
| `refunds` | Full or partial refunds per payment |
| `platform_fee_configs` | Versioned platform fee schedule per service type |
| `platform_fee_records` | One per completed booking: fare, platform fee, community fee, processing fee, driver net, settlement status |
| `community_statements` | Statement per (community, period); fee records link to it so trips are never statemented twice |
| `notifications` | In-app notifications |
| `support_tickets` | Support, incident and safety tickets |
| `feature_flags`, `platform_settings` | Flags and JSON settings (e.g. `fare_caps`) |
| `audit_logs` | **Append-only** audit trail (actor, role, community, action, entity, before/after with secrets redacted, IP, request id) |
| `geocode_cache` | Cached geocoding responses (7 days) |

## Relationship sketch

```
cities 1─* communities 1─1 community_policies
communities 1─* community_admins *─1 users
communities 1─* community_memberships *─1 drivers 1─1 users
communities 1─* vehicles 1─* driver_vehicle_assignments *─1 drivers
communities 1─* pickup_points 1─* route_stops *─1 shared_routes 1─* route_schedules 1─* shared_trip_instances
communities 1─* fare_rules (shared rules → shared_routes)
communities 1─* governance_proposals 1─1 fare_proposals; governance_proposals 1─* governance_votes
users(passenger) 1─* bookings *─1 communities; bookings *─1 drivers; bookings *─1 fare_rules; bookings 1─1 fare_quotes
bookings 1─* booking_assignments / booking_status_history / seat_reservations / trip_events / payments / complaints
shared_trip_instances 1─* seat_reservations, bookings
payments 1─* refunds; bookings 1─1 platform_fee_records *─1 community_statements
```

## Integrity guarantees enforced by the database

| Guarantee | Mechanism |
|---|---|
| A seat is never allocated twice | Unique index on `seat_reservations.activeSeatKey` |
| A departure is never overbooked | Row lock on the trip instance + `CHECK seatsBooked ≤ capacity` |
| A booking is never charged twice | Unique `payments.successKey`; unique `payments.idempotencyKey` |
| Retried booking requests don't duplicate | Unique (`passengerId`, `idempotencyKey`) on bookings; quotes are single-use |
| Fee recorded once per trip | Unique `platform_fee_records.bookingId` |
| Departures generated once | Unique (`scheduleId`, `departureAt`) |
| History cannot be rewritten | `BEFORE UPDATE/DELETE` triggers on `audit_logs` and `fare_history` raise errors |

## Migrations

| Migration | Contents |
|---|---|
| `20261024165604_init` | Full schema (generated by Prisma) |
| `20261024170000_immutable_audit` | Append-only triggers; `CHECK` constraints on seats, ratings and seat counts |
| `20261030173513_policy_proposals_and_route_paths` | `governance_proposals.policyChanges` / `policyBefore` (JSON) for rule-change proposals; `shared_routes.pathGeometry` (JSON `[lat,lng][]`) / `pathDistanceMeters` for road paths |

Apply with `npm run db:migrate` (`prisma migrate deploy`). Create new migrations with `npm run db:migrate:dev -w apps/api -- --name <change>`; hand-written SQL (triggers, checks) goes in its own migration folder.
